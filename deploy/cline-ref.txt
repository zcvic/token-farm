# ---- 2026-11 首次接入
#      基线：首次接入时参考仓 HEAD（具体提交号待补）。

#      已取（按能力，不是逐行移植）：
#        · WorkOS 设备授权码：
#            POST https://api.workos.com/user_management/authorize/device
#                 client_id=client_01K3A541FN8TA3EPPHTD2325AR（公开值，与官方
#                 客户端一致）
#              → device_code / user_code / verification_uri_complete / interval
#            POST https://api.workos.com/user_management/authenticate
#                 grant_type=urn:ietf:params:oauth:grant-type:device_code
#              → authorization_pending / slow_down / access_denied /
#                expired_token / access_token
#          → client.start_device / poll_device、login.py
#        · 换 Cline 凭证：POST {api}/auth/register
#            {accessToken, refreshToken}（WorkOS token）
#              → data.refreshToken（后续对话全靠它；WorkOS token 不进账号文件）
#          → client.register_sync（`device_exchange_sync` 是它的别名）
#        · 上游：https://api.cline.bot/api/v1，OpenAI 兼容。
#          授权头是 `Bearer workos:<accessToken>`（注意 `workos:` 前缀）。
#          → client.chat_headers
#        · **必须伪装 Cline 客户端头**，缺了会被 403
#          `only available via Cline product surfaces`：
#            User-Agent: Cline/3.0.47、X-CLIENT-TYPE: cline-sdk、
#            X-CLIENT-VERSION: 3.0.47、X-PLATFORM: terminal、
#            X-PLATFORM-VERSION: 3.0.47、X-CORE-VERSION: 0.0.66、
#            X-Task-ID（会话 id）、HTTP-Referer: https://cline.bot、
#            X-Title: Cline、X-IS-MULTIROOT: false、Accept-Encoding: identity。
#          → constants（伪装头组）+ client.chat_headers
#        · refresh token 是**一次性**的：`/auth/refresh` 换发后旧的立即作废，
#          必须**先落盘再使用**；并发刷新由账号级锁串行。
#          响应 `data.accessToken` / `data.refreshToken` / `data.expiresAt`
#          （可能是 epoch 毫秒或 ISO 串）。
#          → adapter._token_for、client.parse_refresh、store
#        · 免费档（`deepseek/`、`cline-free/`、`cline-pass/` 前缀）**只认流式**：
#          非流式请求会被回 500 `empty response content`。客户端要非流式时，
#          适配器仍按流式发，再用 `sse_to_completion` 聚合成 `chat.completion`。
#          → client.needs_force_stream / sse_to_completion、adapter._chat_once
#        · 免费档请求体**不能带 `max_tokens` / `max_completion_tokens`**
#          （上游直接 500）；`cline-free/` 前缀一律剥掉。
#          → client.chat_body
#        · 上游把限流伪装成 200 正常帧：正文是 `empty response content` /
#          `Daily free limit` / `INFERENCE_CAP_ERROR`，或只有 reasoning 没有
#          正文。这类响应必须判成 429（换号 + 冷却），不能当成功回复交出去。
#          → client.limit_signal / sse_to_completion、adapter._scan_sse
#        · 对话体带客户端自有字段：`session_id`、`reasoning_effort`（默认
#          `high`）。
#          → client.chat_body
#        · 模型目录（两个接口都免鉴权）：
#            GET {api}/models                         全量（含付费档、`:batch`）
#            GET {api}/ai/cline/recommended-models    只取 `free` 分组
#          `recommended` 的免费条目优先，`/models` 补其余；合并后免费排前面。
#          `:batch` 变体丢弃（不是对话模型）。
#          → client.parse_models / fetch_models / fetch_recommended、catalog.merge
#        · 没有余额接口：余额不足由 402 `insufficient_credits` 表达；
#          `credits()` 沿用基类的「不支持」。
#
#      有意不跟：
#        · 不引入 Cloudflare Worker / KV / Durable Objects 运行时。
#        · 不引入参考仓的账号池与面板；选号 / 冷却 / 亲和按 token-farm 口径。
#        · 不实现签到：上游没有签到入口（`supports_checkin=False`）。

# ---- 2026-11 第二批：d5cb69ae → f459f003（取 2 项 + 1 项的被动一半）
#      已取：
#        · d5cb69ae 的 token 自愈部分（落点 server/platforms/cline/client.py
#          的 refresh_via_workos + adapter.py 的 _heal_via_workos）：refresh
#          token 被上游判 `invalid_grant`（用户重登、换设备、后台撤销）时，
#          旧实现只能标账号失效等人工重登。现在改用 WorkOS 的
#          `authenticate` + `grant_type=refresh_token` 再换一次；仍然失败才标
#          失效。**只有** `invalid_grant` 才判 401（网络错误 / 5xx 不消耗
#          refresh token，避免一次抖动把账号永久踢下线）。自愈成功后顺手重跑
#          注册拿新的 access token；注册也失败就退回 WorkOS 给的 access，兜底
#          有效期按 1 小时减 60 秒。触发条件限定在 400/401/403——其余错误与
#          token 无关，不该去消耗一次性的 refresh token。
#        · f459f003 工具名截短与还原（落点 client.py 的 shorten_tool_name /
#          clamp_tool_names / restore_tool_names / SseToolNameRewriter，
#          constants.TOOL_NAME_MAX=64）：Anthropic 侧工具名上限 64 字符，超长
#          名会被上游直接 400。超过 64 的截成「前 55 字符 + `_` + sha256 前 8
#          位」（确定性，同一名字每次得到同一个短名，重试与多轮都稳定）。
#          覆盖 tools[].function.name、messages[].tool_calls[].function.name
#          与 tool_choice；写时复制，不改客户端传进来的原体。响应侧非流式在
#          两条出口还原，流式由 SseToolNameRewriter 按行改写——没有映射时
#          原样返回同一块字节，半行会缓冲到下一块，不影响 SSE 时序。
#        · 68751e7ea 的**被动**可用性信号（落点
#          server/platforms/cline/availability.py 的 `ModelHealth`）：真实请求
#          成功 / 失败各记一次（失败 30 分钟、成功 2 小时保鲜），`list_models()`
#          按「可用 → 未知 → 失败」稳定排序，没有信号时顺序与改造前完全一致；
#          只影响排序，不影响可用性判定，纯内存不落盘。只记模型级失败
#          （404/429/5xx）；401/402/403 是账号或余额问题，记进来会把整池拖下水。
#          流式里伪装成正常帧的限流（`Daily free limit` / `INFERENCE_CAP_ERROR`）
#          没有状态码可看，走 `record_unavailable` 直接记一次失败。
